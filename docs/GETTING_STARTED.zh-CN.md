# 第一轮科研记录

[English](GETTING_STARTED.md) · [文档目录](README.md)

先按 [README](../README.zh-CN.md) 启动应用。下面用一组**合成示例**走通完整流程；开始真实项目时换成自己的研究问题即可。

## 1. 围绕一个问题创建项目

输入研究者令牌。空实例会直接显示创建表单，填写名称和目标，点击 **创建项目**。例如：

- 项目名：文献检索策略的迭代
- 研究目标：关键词扩展能否在不增加噪声的前提下，提高证据覆盖率？

一个项目持续记录这个问题的演进，不必每次实验或每次 AI 会话都另建项目。

## 2. 添加研究路线与尝试

点击 **+ 一级路线**，类型选“问题”或“想法”，用一句摘要描述准备探索的方向。选中保存后的节点，点击 **+ 子节点**，创建一个“尝试”。卡片的右键菜单也提供“新增子节点”。

正在做的工作用“进行中”。完成尝试后点击 **编辑**，分别填写：

| 字段 | 记录什么 | 合成示例 |
| --- | --- | --- |
| 适用条件 scope | 实际验证的范围 | 同一语料库、20 个固定问题、Top-10 检索 |
| 直接观察 finding | 观察或测量结果 | 覆盖率仍为 60%，无关结果增加 |
| 当前解释与决定 decision | 如何理解结果，下一步做什么 | 仅对低召回问题扩展关键词 |
| 证据 evidence | 行内记录、链接或文件引用 | 对照统计，或结果表的路径 |

“当前条件下支持”和“当前条件下不支持”都需要条件、观察、决定和至少一条证据。证据不足时用“尚不能判断”。应用保存你的判断，不会替你验证实验是否发生或证据链接是否一直有效。

点击 **保存**。“收起编辑”只切换阅读模式，不会自动保存。路径证据只是引用，不会上传文件；原始数据需自行保存。

## 3. 画上直接写：草稿卡

点 **+ 一级路线** 或卡片的 **+ 子节点**（右键菜单同样可用）后不用等弹窗：地图上父节点旁直接出现一张虚线的**草稿卡**，右侧面板同时打开同一份表单——两处编辑的是同一份草稿，在哪边写都行。保存之前不产生任何记录。

在草稿卡标题里按 Enter 只是确认输入（中文输入法组词中的 Enter 不会误提交）；⌘/Ctrl+Enter 或点击 **创建** 才真正保存；**取消** 则整张卡消失，不留任何记录。保存成功后草稿卡让位于正式卡片并自动定位。

切换 横向树/纵向树/大纲 草稿不会丢：大纲模式降档为只读虚线行，编辑仍在右侧面板。保存失败（断网或版本冲突）时草稿原样保留、错误显示在面板里，直接重试即可——同一份草稿无论重试多少次，都只会产生一条提交、一张新卡。

## 4. 插入表格与图片

节点详情的正文是 Markdown。编辑工具行的 **插入表格** 会放入一张可改行列表格模板；阅读视图里宽表格在容器内横向滚动，不撑破卡片。

**插入图片** 选择本地图片，或把截图直接**粘贴**进正文输入框——图片上传为受管附件，正文里以 `![名字](attachment:…)` 引用。阅读与预览视图中图片内联显示，点击可放大；图片只经认证接口加载（令牌不进入图片地址），外部 `https://` 图片一律不加载，只显示占位条。上传后**取消**草稿不会产生任何已引用记录，未引用的上传 30 天后自动清理；正式保存后才算「已使用」，已用图片永不删除。

## 5. 保留负结果，继续下一步

保留原来的负结果，在它下面新建子节点：“仅为低召回问题扩展关键词”。新条件下的后续尝试可以得到不同结果；不要因为后来某个变体成功，就把旧尝试直接改成绿色。

**关联** 标签页用于连接不同分支的工作。**历史** 展示当前节点的提交及修改前后内容。搜索可以找标题、摘要、标签、观察和决定；卡片右键菜单可以复制节点深链接。

## 6. 视图与布局

地图上方有一排视图工具（这些设置只保存在本浏览器，不写入科研记录）：

- **一键展开/折叠**：全部展开、全部折叠、展开到第 1–3 层、展开选中节点的分支；批操作后可用 **恢复上次** 一步退回。
- **布局**：⋯ 菜单里可切换 横向树 / 纵向树 / 大纲。三种布局各自记住自己的折叠、分支过滤和缩放视野，切换或刷新后按布局恢复；首开新布局时默认展开两层。
- **信息密度**：默认阅读档随缩小自动降为精简档（隐藏摘要与计数）和概览档（色块 + 路线名叠加，配图例与「放大定位」浮层）；也可在菜单里锁定档位。**低干扰** 隐藏卡片标签与计数。
- **详情面板**：拖左缘可调宽，收起后右侧留有恢复按钮；有未保存修改时按钮带圆点，草稿不会丢。
- **语言**：顶栏 ⋯ 菜单可将界面切换为中文/English；正文内容与 API 字段不翻译。

## 7. 版本与泳道

研究推进到第二、三轮时，可以给方案打**科研版本**标签（v1、v2、v3……）。注意它不是保存记录号——界面上的 **记录 #N** 是每次保存的计数，而 v1/v2 是研究阶段标签，二者无关。

- **标记归属**：打开节点详情 → 编辑，在「科研版本」区点亮版本标签（同一节点可属多个版本），保存后落库；新建节点默认带入当前筛选选中的版本。
- **按版本浏览**：⋯ 菜单「按科研版本筛选」可只看某个版本（含未分配）；命中节点的研究路线祖先会一并显示为上下文，被筛掉的选中节点在详情面板给出提示与一键恢复。筛选跨布局、跨刷新保留，随时选「全部版本」还原。
- **泳道视图**：布局菜单选 **泳道**，得到一张「版本 × 一级线路」进度表——列是版本与「未分配」，行是路线，树边隐藏、折叠/分支过滤不生效；适合一眼看清各轮方案覆盖了哪些路线。

## 8. 交给 AI 接续

打开 **⋯ → AI 接入说明**，获取服务地址、项目 ID 和命令示例。在外部 AI 使用的终端环境中配置它自己的令牌，再交给它下面这段任务。把 `PROJECT_ID` 和“下一步任务”换成实际内容：

> 先读当前仓库的 docs/AI_USAGE.zh-CN.md。使用已经配置好的 RESEARCHMAP_BASE_URL 和 RESEARCHMAP_TOKEN，接续项目 PROJECT_ID。
> 先读取 context，再补读相关节点的完整内容和证据，包含此前的负结果。先概括目前研究进展。
> 对约定的下一步任务，只记录实际发生的变化，先 dry-run，再提交并读回核对。保留旧发现，区分新想法和已完成实验。
> 如果版本冲突，重新读最新内容后解决冲突。不要输出令牌，也不要把令牌写入科研记录。

应用提供共同记录，不会自动连接 AI。外部 AI 工具需要能用 Python 3 执行 [CLI](../tools/researchmap.py)，并能访问同一个服务。另一台机器的 `localhost` 指它自己；远程 AI 需要先建立受信任的连接。

## 9. 核对更新，结束会话

点击应用内的 **刷新** 或 **载入更新**，查看新节点和历史，确认作者是 AI 的令牌名。双方修改同一字段时，逐项核对再保存；不同字段的修改可以合并。

关闭前保存。普通刷新或离开页面时，未保存的节点草稿会触发浏览器提醒，但这不是自动保存，也不能防止浏览器崩溃导致丢稿。整页刷新后需重新输入令牌，已保存的项目仍留在服务端。

不再需要的叶子节点可以归档，历史会保留。通过 **⋯ → 显示已归档节点** 找到并恢复它。升级前先按[备份指南](OPERATIONS.zh-CN.md)保存一份副本。
