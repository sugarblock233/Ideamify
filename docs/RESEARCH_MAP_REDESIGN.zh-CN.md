# 科研版图改造交付书

日期：2026-09-16。状态：**待实施的产品与工程设计**。本批只交付文档，本文中的新界面、接口增量和验收场景均不代表已经实现或通过验证。

给实施 AI：先读本文，再读 [研究内容编写指南](RESEARCH_AUTHORING.zh-CN.md)、[现行规格](SPEC.md) 和 [仓库协作约定](../AGENTS.md)。本文定义下一轮改造的目标和范围；现行产品事实仍以代码和现行规格为准。实施时在同批更新 SPEC、DECISIONS 和中英文使用指南，不得把这份提案直接当作已上线能力。

## 1. 交付目标：研究者能够指导研究

主要使用者是一位未必亲自编写代码、运行实验的研究负责人。他打开项目，应当先理解研究问题、主要路径和判断依据，随后决定下一步关注哪里。

这轮交付必须让他完成三个任务：

1. **看全局**：项目想回答什么，有哪些主要路线，各条路线为什么值得探索，目前知道什么、缺什么。
2. **顺着思路读**：从一个大方向进入具体问题，理解某个假设如何被检验，观察如何改变判断，又引出什么问题。
3. **按需核实**：需要时再打开方法、代码、运行条件和原始证据，并能分辨提议、实现、实际执行与研究结论。

不以节点数量、树深度、绿色比例或新增视图数量衡量成功。研究未完成时，地图也应清楚、有用。

## 3. 研究信息模型

### 3.1 两种结构同时存在

**归属树**回答“它主要解决哪个上位问题”。建议内容从项目目标，进入大路线、子问题、可检验假设，再到必要的尝试与后续问题。

**研究承接关系**回答“为什么从这里走向那里”。它来自节点的 rationale/decision，以及有明确 reason 的 motivates/supports/contradicts/depends_on 关系。两者可以重合，也可以跨分支。

```mermaid
flowchart LR
    P[项目：如何提高证据覆盖并控制噪声] --> R[路线：改善查询表达]
    P --> S[路线：改善结果筛选]
    R --> Q[子问题：同义词缺失是否导致漏检]
    Q --> H[假设：受控扩展可以补回相关证据]
    H --> T[尝试：固定集合上的对照比较]
    T --> F[观察：覆盖增加但无关结果也增加]
    Q --> Q2[新问题：扩展应在什么条件下触发]
    F -.启发：噪声代价使触发条件成为问题.-> Q2
    F -.启发：需要检查候选结果的筛选.-> S
```

全部为合成示例。实线只表示归属，虚线才表达已登记的研究承接。这里的“路线、假设”是内容角色，不是新增 API kind。不要把示意图机械转换成每条路线都必须具备的七级模板。

### 3.2 深入的条件

- 子节点必须使问题更具体，或引入一个会影响判断的新问题、方法变体、可复用发现。
- 同一尝试的执行细节和直接结果通常更新原节点。只有结果有独立价值或需要被多处引用时，才拆为 finding。
- 参数小改、文件名、运行批次和代码模块通常进入详情或证据；方法假设或适用范围实质改变时才拆节点。
- 研究可以是文献比较、理论推导、数据检查、定性观察或实验，不强迫每条路线经过“写代码→训练”。
- 未知问题允许停在任何深度；增加无意义的中间标题、虚构结果或下一步都不能算深入。
- 首次规划一般给出 2–5 条可区分的大路线，每条先展开必要的子问题；这是编写建议，不是 UI 或数据库限制。

### 3.3 顶层综述是研究内容

一级路线仍是 `parent_id=null` 的普通 question/idea 节点。其 summary 描述“要解决什么及当前认识”；rationale 描述价值与依据；finding 概括有来源的观察；decision 写当前取舍与下一步；scope 写适用范围及未知。

外部 AI 在授权任务内形成会改变路线判断的新发现时，应检查相关路线综述是否需要更新。可以在同一 commit 中提交叶子变化、承接关系和必要的祖先摘要修订。没有判断变化就不更新祖先，也不把子节点状态自动向上传播。

只有建立了清楚的研究表述，路线才适合使用 supported/not_supported。一个“改善查询表达”的宽泛方向通常保持 in_progress 或 inconclusive；某个子实验成功不意味着整个方向已被证实。

### 3.4 实现、执行和证据的区别

| 可见资料 | 可以写什么 | 不能推出什么 |
| --- | --- | --- |
| 设想或实验方案 | 待验证的方法、预期区分的假设 | 实验已经执行 |
| 脚本或配置 | 方法已经实现；代码打算检验什么 | 脚本运行成功、研究结论成立 |
| 日志或运行报告 | 来源记录了某次执行，列出条件和缺口 | 指标有效、因果解释成立 |
| 可追溯结果及有效对照 | 在说明的范围内，观察支持/不支持某陈述 | 在其他数据、预算、任务上同样成立 |
| 用户回忆或无法打开的引用 | “据研究者回忆”或“来源未核验” | 已核实的实验事实 |

这些是编写规范，不是新增 NodeStatus。状态继续使用原六种值；`evidence_count > 0` 只表示有引用，不能显示成“已验证”。纯代码事实可以被代码引用支持，但必须把事实表述限定为“已实现某行为”，不能偷换成效果结论。

## 4. 阅读方式：总览、路线、证据

### 4.1 推荐主入口

保留项目管理页。进入一个项目后，新增“研究阅读”作为首次默认工作区；保留一个明确的“地图”入口访问原四种布局。用户选择过的模式按项目记忆，不强制覆盖已有地图偏好。

研究阅读内部只有“总览”和“路线阅读”两种导航状态。它们使用同一份节点数据和同一编辑会话，不复制一套内容，不另建研究项目。

| 区域 | 内容与职责 |
| --- | --- |
| 项目栏 | 项目名、搜索、研究阅读/地图、载入更新；编辑与版本等次要动作可收进菜单 |
| 左侧路线目录 | 全部一级路线的名称、文本状态和定位入口；默认约 208px，可收起 |
| 中间阅读区 | 总览的目标及路线卡，或当前路线的前因、焦点问题和下一步选择 |
| 证据/编辑区 | 用户主动打开时出现；1440 宽可用右栏，1280 宽优先抽屉或覆盖面板 |

不能让详情面板默认占用近半个屏幕，也不能用全图缩小来容纳不断增长的项目。

### 4.2 总览：先回答研究负责人最关心的事

顶部显示项目目标，建议目标正文包含研究问题、成功判断和约束。长目标提供展开；没有内容时显示“尚未填写”，不自动生成。

路线卡按现有 `(order_index, id)` 顺序展示：

1. 路线名称与范围：title、summary。
2. 当前判断与下一步：该路线节点的 decision，可展开完整内容。
3. 节点已有文本状态，以及“该路线摘要更新时间”。
4. “进入路线”与“查看依据”入口。

1440×900 和 1280×800 均优先两列路线卡；单卡至少 360px，空间不足回落一列。卡片按行从左至右读，默认正文至少 15px，无需缩放。首屏显示目标和前 2–4 条路线；其余正常滚动，所有路线在目录可达。六条以上路线分页或按批追加，不能把数量限制为六条。

不展示“已完成 83%”等由节点状态拼出来的研究进度。节点总量、保存次数、版本覆盖可留在辅助信息中。

当后代的 updated_at 晚于路线自身 updated_at 时，可以显示“下级有较新记录，综述可能需复核”。这是一个时间提示，不证明摘要错误；同一 commit 更新产生的相同时间不触发。不要自动生成新综述。

### 4.3 路线阅读：一个稳定的阅读窗口

```text
项目目标                                      研究阅读 | 地图
路线目录     总览 / 查询表达 / 漏检原因 / 受控扩展
             所属问题路径：路线 → 子问题 → 当前假设
             路线当前判断：……                 查看路线综述

             由何而来：来源节点 + 承接原因       返回来源
             当前问题或判断
             为什么研究它 / 直接观察 / 当前决定 / 适用范围
             查看方法与证据                    编辑

             继续深入（归属子问题）
             [子问题 A + 摘要] [子问题 B + 摘要]  查看其余
             由此引出的方向（已登记的启发关系）
             [后续问题 + 启发原因]              查看全部关系
```

- 目录、顶部路径保持在屏幕内；主阅读区推荐 680–960px。路径太长时保留路线、当前父级和焦点，中间收进可展开列表，能访问所有祖先。
- 当前焦点正文使用正常文档流，可纵向滚动。标题允许换行；rationale/finding/decision/scope 分段展示，不塞进缩放卡片。
- 下方子问题按同级顺序排两列短卡，最多先显示 6 个，再追加；点击一个子问题，把它移入同一个焦点阅读位置。深度增长不增加水平滚动距离。
- “所属问题路径”可以由 parent_id 得到；“由何而来”和“由此引出”只展示实际关系及方向。没登记关系时显示“尚未记录承接关系”，仍可根据 rationale 阅读，不能把父子箭头改称因果链。
- 进入路线先看路线本身，之后恢复用户上次读到的位置时显示“继续上次阅读”。不能按最新时间、最深层、最高成功比例自动宣称哪条是“主线”。
- 焦点可以缺少某些内容字段，但必须区分“作者未填写”和“请求尚未加载/失败”。若已有 summary 以外的字段，默认展示完整短字段；较长段落可明确折叠，展开不切走当前问题。
- 同级备选始终可回到上位问题选择；跨路线跳转显示来源路线和返回入口。关系成环时只提供局部导航，不递归自动展开成无限流程。
- 负结果保留在所属位置，后续变体可继续深入；显示其限定条件。后续节点不能覆盖掉引出它的失败。

这里使用纵向滚动承载文字，但不沿纵向铺满整棵树。空间关系服务于阅读：先比较路线，再在固定窗口内选择下一步，随时回溯研究依据。

### 4.4 证据详情

打开“查看方法与证据”后，按以下顺序呈现：

1. 人能读懂的方法说明、比较对象及适用条件。
2. 直接观察与解释的区别；缺少结果就明确显示缺口。
3. evidence 的 label、note 和引用内容；path 只提供复制，附件沿用现有加载规则。
4. details_md 的完整技术内容、脚本说明、运行信息和表格；历史在独立标签页中。

代码引用说明其用途、输入输出、要验证的问题，以及是否有执行依据。应用只展示已填写信息，不能从扩展名推断是否运行，不能自动抓取路径或启动实验。

### 4.5 地图辅助视图的调整

- 横向树用于看分叉与归属全貌；纵向树、大纲、版本泳道继续保留。版本是阶段标签，版本列顺序不表达论证关系。
- 地图默认不因切换到阅读模式而清掉折叠、分支过滤或视口；返回时恢复锚点。
- 新增“沿当前路径展开”和“再深入一层”；保留全部展开，但它不是大项目的推荐入口。
- 若保留“展开到 N 层”，N 是可见节点的最大相对层级：项目下一级路线为 1；聚焦分支时分支根为 1；深度 N 的节点折叠其子节点。分别验证 N=1、2、3、6 和分支聚焦。
- 层数不是研究角色：第 3 层可能是问题、方法或发现。不要硬编码某一深度必须是什么类型。

## 5. 导航、筛选与编辑合同

| 场景 | 必须发生的行为 |
| --- | --- |
| 首开、无节点 | 展示项目目标和“建立研究路线”的短指引；示例只是合成参考，不自动填入项目 |
| 首开、有节点、无阅读记录 | 显示总览；既有明确地图偏好可继续进入地图，并给出研究阅读入口 |
| 深链接或搜索命中第 8 层 | 直接进入焦点，完整祖先可达；不要求手工展开前七层 |
| 下钻再返回 | 恢复父级焦点、子问题列表滚动位置和来源；切换路线不丢上次位置 |
| 版本筛选 | 延续现有祖先闭包；祖先标明“上下文”。焦点不匹配时明确提示并提供恢复全部版本 |
| 阅读时跨关系跳到筛选外节点 | 明示目标不在筛选内，用户选择查看后才解除相应筛选；返回来源可恢复原筛选 |
| 节点已归档或不存在 | 明确说明、提供返回路线；需要用户选择才能显示归档内容，不静默跳到别的节点 |
| AI 更新到达 | 提示“有新的记录”；显式载入后更新。保留阅读锚点和草稿，不自动跳到最新节点 |
| 编辑中切模式/路线 | 沿用统一草稿保护；同一对象共用一个 draft，不创建读模式专属写入通道 |
| 创建失败、冲突、重试 | 沿用 request_id、revision、dry-run 和差异合并规则；草稿可恢复 |

屏幕上不同时铺开全局路线树、层级列、版本网格、关联网、阅读正文。搜索、返回和查看证据三项应始终容易找到。

## 6. 数据和接口：本轮最小增量

### 6.1 复用现有业务模型

本轮不新增节点 kind、状态、实验表、固定层级角色、科学置信分数或研究执行系统。读模式按明确字段展示内容，不解析 Markdown 标题或 tags 来冒充稳定数据库结构。

| 阅读信息 | 数据来源 |
| --- | --- |
| 项目问题与边界 | Project.objective |
| 路线、祖先、子问题、顺序 | graph 中 parent_id/order_index/id/title/summary/status |
| 路线取舍、研究动机、观察、条件 | NodeFull 的 rationale/finding/decision/scope |
| 方法、代码和证据 | NodeFull.details_md/evidence 及既有附件接口 |
| 承接与交叉证据 | 节点 relations 的 kind/direction/reason/other |
| 版本范围 | 原 version_ids 与 filterNodesByVersion |
| 阅读位置、视口 | 浏览器偏好；不是科学事实或唯一内容存储 |

第一阶段用现有 graph/node/relations/commits 即可实现读取；graph 不包含全部短字段，禁止假设它已有 decision。总览首批最多加载 6 条路线全文；路线阅读只加载焦点、所需路线综述及焦点关系第一页。祖先和子问题短卡使用 graph。不要为 1000 个节点逐个请求全文，也不要用 export 作为页面数据源。

请求按 `(project_id, project_revision, node_id)` 缓存并去重，同时最多 4 个详情请求。切换焦点取消请求或忽略过期响应。读接口失败在对应区域给出重试，不把空白冒充没有数据。NodeFull 已包含 details_md，现阶段虽可折叠显示，却不能声称网络没有下载正文。

### 6.2 一致性与外部 AI 上下文增量

第二阶段必须完成以下小幅读取改进；不新增写入协议或数据库迁移：

1. **relations 响应增加 project_revision**。当前节点关系分页响应没有该字段，不能假设与 graph 属于同一快照。新字段与当前读事务一致，前端类型同步；分页的 PAGINATION_STALE 处理保留。
2. **context 的 focus 增加 rationale**，沿用预算分档、省略提示和 `node` 补读；`details_md` 仍不进入 context。
3. **context 增加 route_context**，使用与其他分组一致的数组形式，最多 1 项：`id`、`title`，以及预算允许的 `summary`、`decision`、`scope`。它表示焦点所属的一级路线。无焦点或焦点本身就是路线时返回空数组；此时分别使用已有 routes 或 focus，不重复填全文。无焦点的 routes 条目增加预算允许的 decision，不拉取全项目正文。
4. route_context 的 id/title 已在祖先骨架中，新增分组不必强制保留一份重复骨架。短字段上限建议 summary 280、decision 500、scope 300 字符，超出沿用截断标记。整项放不下则返回空数组，`omitted_counts.route_context=1`，并提供可执行 `GET /api/v1/projects/{pid}/nodes/{route_id}` continuation；不适用或完整返回时该省略计数为 0（可以省略零值键）。字段因预算被省略时也须列入 warnings 并提供补读，不能把缺字段写成作者未填写。
5. 保持原焦点/祖先骨架完整、min_required_chars 错误、全响应字符预算和旧字段兼容；新增字段也计入预算。关键词模式保留关键词优先；focus 的 scope/finding/decision 等既有高优先内容、反证和依赖优先于额外路线长摘要。rationale 与路线内容不足时让客户端补读，不挤掉全部反证。
6. CLI 的 JSON/Markdown 输出均支持新增信息；Markdown 仍显示省略及补读指引。旧客户端忽略新增字段应能继续工作。

读模式组合 graph、node、relations 时，只把 project_revision 相同的数据作为当前同一版研究展示。revision 不一致时，保留原完整可读版本并提示载入更新；没有旧版缓存的区域显示加载/版本变化提示。显式刷新且无脏草稿时可整体重取一次，持续变化则提示重试，不能无限追赶。第一阶段关系区域只能标明独立读取，完整一致性验收要等本节完成，不能提前宣称已达标。

关系页默认 20 条，有 has_more 时必须可继续读取并显示未读状态。不能把第一页筛出 0 条 motivates 写成“没有后续”。列表按类型分组只对已读取集合成立；完整性通过分页获得。接口不根据关系自动推理研究主线。

### 6.3 浏览器偏好

建议在 `ProjectViewPrefs` 的新版本中新增 `workspaceMode: research|map`；旧 layout 的 h/v/outline/swimlane 含义原样保留。不要把研究阅读混入已有 `density=reading`，两者职责不同。

读模式导航单独存 overview/route、focusId、每条路线的最近阅读位置及滚动锚点，按项目隔离。升级时有旧 layout 明确偏好者默认保留 map，无旧偏好者默认 research。读取旧数据、损坏缓存、节点移走/归档/删除后都应安全回落到总览，不能迁移或改写科研节点。

## 7. 使用指南和内容整理交付

[研究内容编写指南](RESEARCH_AUTHORING.zh-CN.md) 是本批已经可用的内容规范，使用现有字段和 CLI。中英文 AI_USAGE、GETTING_STARTED 与 README 必须指向它。

应用内“AI 接入说明”的交接文本也应在实施阶段同步：先交代目标和大路线，展开当前子问题，核对资料能证明到哪一步，提交研究增量，最后用负责人能理解的语言交接。仅修改仓库 Markdown 而保留界面内的旧提示不算该项完成。

编辑表单同步加入轻量写作帮助，复用现有字段，不增加强制审批：创建一级路线时提示“解决什么、为何值得研究”；创建子节点时展示所属问题并提示“这一步如何推进它”；rationale 提示动机与比较目的，finding 提示只写直接观察，decision 提示取舍与下一问题。未执行的尝试给出“方案/代码已有，结果未知”的合成占位示例。帮助文本必须双语且可忽略，不把模板默认内容保存成真实研究。

对旧地图的整理：

1. 只读当前图与相关资料，列“现有节点 → 建议所属路线 → 研究意义 → 来源可信程度”。代码密集但含义未明的节点先标注待梳理，不自动丢弃。
2. 给出有限的顶层路线草案和一条深入示例；资料不足处明确标注，不能补造历史。
3. 在用户授权范围内通过小批 commit 新建必要的路线节点、`node.move` 归属、修订摘要、补充实际承接关系。保留 ID、证据、版本、历史和人工备注。
4. 重组已有研究数据需要该数据的授权；本轮开发只能使用 scratch 数据和合成案例。开发任务本身不授权接触真实研究数据库。
5. 不为简洁批量归档未知内容；归档依旧只允许叶子、写明原因。拆分新的独立研究单元时注明源节点，避免把一个证据复制成多份独立验证。

| 阶段 | 工作 | 主要落点 | 完成证据 |
| --- | --- | --- | --- |
| A：阅读闭环 | 合成数据、总览、路线阅读、证据入口、连续下钻返回、共享编辑、偏好兼容 | Workspace、SidePanel、TopBar、viewPrefs、styles、双语字典；可新建 ResearchOverview/RouteReader/ResearchEvidence 组件与纯读取模型 | 6–8 层案例能读通；两个视口真实浏览器检查；前端检查通过 |
| B：完整语义 | 关系 revision、context rationale/route_context、分页与一致性、地图展开层级语义修正 | backend views/context、api/types、CLI、expandTools、ViewToolbar；对应测试 | HTTP/CLI 回归、预算边界、关系第 21 条、层级可见结果验证 |
| C：内容与交接验收 | 界面内 AI 说明、示例、旧地图整理演练、使用指南、SPEC 增补、DECISIONS 与变更日志 | examples、e2e、文档、AI 接入说明所在组件 | 非执行者阅读任务与外部 AI 整理任务有记录；发布候选的回归与浏览器验收完成 |

实现前核对当前分支和手动改动。不要照表机械新增文件，能复用已有组件就复用；但也不要继续把所有状态和渲染堆进 Workspace。先提取可验证的读取模型，再连接视图。现有地图的布局算法只修改本轮必需的展开语义。

本轮排除：内置 LLM、自动读取真实代码仓库、训练执行、时间轴、全局自动推理网、自动完成率、角色权限系统、强制重写所有历史节点、部署发布。未来若要持久化“人工指定的重点阅读链”或单独记录执行阶段，应另作数据模型决策；当前阅读路径只是导航，不得伪装为共享科学事实。

## 9. 验收数据与场景

所有数据标记“合成”，由普通 API/CLI 提交到 scratch DB；不使用真实研究内容或真实凭证。

至少准备四类 fixture：

- **有意义的小图**：3 条路线，约 25–40 个节点，一条 6–8 层链；包含未执行代码、限定负结果、由负结果引出的新问题、跨路线发现、相互冲突的证据和仍未知的分支。附标准答案，禁止靠“节点 1/节点 2”冒充研究案例。
- **旧式记录图**：代码/批次名较多，包含人工备注和没有来源的历史回忆，供重组前后比较。
- **边界图**：空项目、单路线、80 个同级子问题、64 层路径、65 层非法创建或移动、关系环、超过 20 条关系、归档目标、长中文标题及长英文单词。
- **大图**：复用 1104 节点压力 fixture，另补路线阅读需要的合成摘要；评估请求数与实际交互，不要求给每个压力节点编写完整论文叙事。

| ID | 检查 | 通过标准 |
| --- | --- | --- |
| R01 | 不参与实验的人看总览 | 60 秒内能说出目标、主要路线差异、至少一条路线的判断与未知；无需打开脚本。记录回答和困难，不能由截图替代 |
| R02 | 沿研究过程深入 | 在小图上读到第 8 层，能说清上位问题、一次转向原因、当前证据和下一步；返回时位置可恢复 |
| R03 | 有代码无运行记录 | 编写结果明确“已实现、未确认执行”；界面显示已填缺口，不能显示“实验成功”或伪造指标 |
| R04 | 一个负结果引出两个备选 | 两个方向均可达，原失败条件保留；父路线状态没有自动变红或变绿 |
| R05 | 归属与论证不同 | 没有 motivates 的父子关系只显示归属；真实 motivates/depends_on 的双向文案正确，关系环不造成无限展开 |
| R06 | 深度与折叠 | “到 N 层”可见深度严格为 N；逐步下钻到 64 层可用；65 层及使后代越界的移动按后端约束拒绝 |
| R07 | 搜索、链接、筛选 | 第 8 层、筛选外节点、跨路线返回、归档节点均有明确状态，祖先不丢失 |
| R08 | 双语与桌面宽度 | 1440×900、1280×800，浏览器 100%；默认可读、无页面横向溢出；主要动作可见、键盘可达、有文字状态；打开证据不挤坏正文 |
| R09 | 更新、冲突与草稿 | 快速切节点不会被迟到响应覆盖；AI 更新不强制重排；切换模式草稿不丢；失败重试只提交一次 |
| R10 | 1000+ 节点与宽分支 | 首批详情请求 ≤6、并发 ≤4，正文组件不按全图规模挂载；20 次暖缓存下钻 p95 ≤300ms，记录设备/浏览器/网络条件和真实测量 |
| R11 | 关系分页与一致性 | 第 21 条的关键承接关系可读到；has_more 时不宣称没有关系；混合 revision 不展示成同一版完整判断 |
| R12 | AI 接续上下文 | rationale 与路线判断可读或有诚实补读指引；4000/12000/50000 字符预算内无静默遗漏、原祖先骨架完整，低预算不吞掉全部反证 |
| R13 | 旧图整理与追溯 | 原 ID、历史、证据、版本和人工备注可核对；重组不新增不存在的实验结果；可从新路线找回原资料 |
| R14 | 非实验型研究 | 一条文献/理论比较路线也能形成问题→论据→判断→新问题，无实验节点也可正常阅读 |

R01/R02 是实际阅读任务：先让未参与该案例编写的研究者尝试。若当时没有合适读者，开发 AI 可做独立会话的可用性预检查，但必须报告“人工阅读验收未完成”，不能替用户宣称易读。

## 10. 验证与交付规则

前端改动运行 `npm test`、`npm run build`；UI 改动还运行 Playwright 并在真实浏览器检查上述两个视口。后端/context 改动运行 `pytest`，CLI 增量通过 scratch 服务执行真实读取检查。已有回归继续通过；新测试检查用户可见结果，不只复述内部集合。

记录每阶段实际执行的命令、结果、截图和未完成验收项。性能记录区分冷加载、网络耗时和本地导航；禁止把静态布局计算耗时当成整个页面性能。测试截图由合成数据生成，不复用旧截图冒充新视图验收。

交付清单：新阅读闭环、现有地图回归、接口与 CLI 兼容、合成数据和标准答案、研究负责人阅读结果、AI 内容整理前后对照、中英文说明、SPEC 增补与 DECISIONS。存在未完成项时明确说明影响及下一步；不自动部署、推送或发布。
